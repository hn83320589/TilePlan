# 01 需求分析

這一章記錄 TilePlan 要解決什麼問題。需求的主要來源是開發對話一開始使用者貼上的題目（以下簡稱「題目」），其次是外部審查意見與測試報告。

## 背景與目標

> 📄 依據：對話中使用者貼上的題目

客戶是一個三人泥作工班，主要接老公寓浴室與廚房的翻修。他們目前的流程是在現場用捲尺量牆長，回去用紙筆畫圖、估算要叫幾箱磚、再寫報價單。

> 📄 依據：`docs/architecture.md` §1.1（開發前與使用者討論後確認的分析）

| 角色 | 情境 | 痛點 |
|---|---|---|
| 師傅（現場） | 用捲尺量牆長、對角線 | 老公寓牆角不是直角，紙筆畫不準 |
| 師傅／老闆（回去後） | 排版、算叫幾箱磚、報價 | 叫太多浪費、叫太少要補貨，補到的批號顏色不同 |
| 業主 | 看報價單 | 要能列印、看得懂、數字對得起來 |

**核心價值**：從「現場量到的數字」一路走到「可以下單的箱數」與「可以交給業主的報價單」，中間每一步都能追溯、能驗證。

| FR-04 | 可加入多邊形的不鋪設區（柱子、浴缸、廚具底座） | 📄 題目 |

| FR-06 | 磁磚規格：長、寬（cm）、厚度、縫寬（mm）、每箱片數、每箱單價 | 📄 題目 |

## 範圍外

> 📄 依據：`README.md`「已知限制」

- 只處理地坪，不處理壁磚、轉角收邊、洩水坡度。
- 實測輸入的對角線只能「頂點到頂點」，不支援量到牆中間某一點。
- 切割片切齊牆面，不另留伸縮縫（實務上由踢腳板或矽利康收邊）。
- 餘料只在同一房間內重用，不跨房間。
- 只支援桌機版 Chrome／Edge 的滑鼠操作。
- 不需要資料庫、Docker、登入（題目明列）。

## 開發中確認過的需求細節

題目沒有說清楚、開發前用問答與使用者確認的四件事，後來都寫成決策紀錄：

> 📄 依據：對話中使用者的選擇；`docs/architecture.md` 決策 D1–D4

| 問題 | 決定 | 理由 |
|---|---|---|
| 同一種磁磚用在多間房，箱數怎麼算？ | 跨房間合併片數後才換算箱數（D1） | 一次叫貨同批號、避免色差；各自進位會多叫 |
| 工資用的坪數取幾位？ | 用報價單上顯示的兩位小數坪數（D2） | 業主可以拿報價單上的數字自己驗算 |
| 基準線決定什麼？ | 只決定磚縫方向，兩軸偏移由程式自由最佳化（D3） | 最容易同時滿足對稱與 ≥ 1/3 |
| 黏著劑、填縫劑怎麼計價？ | 依包裝計價，包數無條件進位（D4） | 符合實際叫貨方式 |

## 未解決或待確認的需求問題

以下沒有在對話或文件中被討論過，列出來供日後確認：

- 🔍 **損耗率是否應該依切割比例調整？** 目前只依鋪法給固定比例（5%／10%），切割片很多的小房間可能低估。程式支援逐間覆寫（`Room.WasteRateOverride`），但沒有自動建議。
- 🔍 **餘料能否跨房間？** 同一種磚在浴室切剩的料，實務上可能拿到廚房用。目前 `OffcutPlanner.Plan()` 一次只處理一間房的 `LayoutResult`。
- 🔍 **報價單的稅與付款條件？** `QuoteBuilder` 只算材料與工資，沒有營業稅、運費、拆除費等欄位，推測題目範圍不含這些。
- 🔍 **牆面有門檻、地排時如何處理？** 目前只能用不鋪設區近似，不鋪設區的邊緣會被當成要檢查切條的邊（可關閉）。
